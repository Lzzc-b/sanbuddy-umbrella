# 商业模式与实施路线（学生阶段调整版）

> 适用说明：本文件用于替换 / 附录于 V4 方案中的「商业模式」「实施路线」章节。  
> 原则：**本学期以学习与验证为主，不开展真实收费与规模化运营**；原公司级营收测算保留为远期参考。

## 一、价值假设与验证方式（原「商业模式」调整）

### 1.1 本阶段定位

伞伴（SanBuddy）在学生项目阶段**不设收入目标**。  
当前目标是验证三件事：

1. 用户是否接受「先是好伞，其次才是智能」；
2. 「安静防丢 + 最后出现位置」是否好懂、是否够用；
3. 丢伞后的可选兜底服务，是否有人愿意付费（只测意愿，不收款）。

### 1.2 价值假设（待验证，非已证实）

| 假设 | 内容 | 本阶段如何验证 |
| --- | --- | --- |
| H1 好伞优先 | 用户更在意伞本身好不好用，而不是智能噱头 | 访谈/问卷：「更像普通好伞还是电子产品？」 |
| H2 安静防丢有用 | 离开常驻点未带伞时提醒，比频繁推送更可接受 | 演示提醒规则后询问是否觉得烦 |
| H3 非实时定位可接受 | 用户理解并接受「最后位置 ≠ 实时追踪」 | 提问正确率（理解题） |
| H4 订阅非必买 | 基础功能不依赖订阅；订阅只在失物时出现 | 演示失物页后询问是否感到被推销 |
| H5 远期收费可能成立 | 硬件合理利润 + 可选年费/换面/按次服务 | 意愿价收集；样本不足不作营收结论 |

### 1.3 远期商业设想（附录，非本学期交付）

若未来进入真实试点，可沿用 V4 方向：

- 硬件：合理利润定价（非补贴）
- 服务：失物场景可选订阅（如 ¥99/年）
- 备选：换面服务、企业定制、按次增值

**本学期明确不做：** 真实支付、订阅履约、云端商用、规模获客、单位经济测算拍板。

### 1.4 学生阶段「商业」交付物

- [ ] ≥10 份问卷 **或** ≥5 次用户访谈纪要  
- [ ] 汇总：理解度 / 打扰感 / 付费意愿  
- [ ] 结论三选一：继续探索订阅 / 改为一次性增值 / 暂缓服务收费

## 二、学期实施路线（原「实施路线」调整）

把原「0–12 个月公司路线」拆成**本学期可完成**的四段。原 12 个月路线仅作远期附录。

### 阶段 A｜概念与原型（约第 1–2 周）

**目标：** 方案说得清，原型点得通。

| 任务 | 完成标准 | 建议提交说明 |
| --- | --- | --- |
| 整理 V4 方案入库 | `docs/product-v4.md` 可读 | `docs: 添加伞伴 V4 产品方案` |
| 放入交互原型 | 可双击 HTML 打开 | `feat: 添加 V4 可交互原型` |
| 标明模拟边界 | 写清蓝牙/天气/位置均为模拟 | `docs: 说明原型模拟边界` |
| 手动测试表 | 引导→落伞→寻伞→电量→失物均可走通 | `test: 完成原型手动测试记录` |

**本阶段不做：** 真实蓝牙联调、小程序上架。

### 阶段 B｜真伞最小硬件验证（约第 3–5 周）

**目标：** 用「真伞 + 市售 BLE 防丢标签」验证防丢/寻物，不自研主板。

| 任务 | 完成标准 | 建议提交说明 |
| --- | --- | --- |
| 选型采购 | 记录伞型、标签型号与价格 | `docs: 记录真伞与标签选型` |
| 安装实拍 | 安装位置照片（建议本人同框） | `docs: 上传真伞安装照片` |
| 分离提醒实测 | 离开一定距离有提醒，记录环境与结果 | `test: BLE 分离提醒实测` |
| 声光寻物实测 | 可触发寻物，记录是否听得见/看得见 | `test: 声光寻物实测` |
| 对照 V4 清单 | 标注已验证 / 仍模拟 / 本学期不做 | `docs: 更新功能验证清单` |

**本阶段不做：** 自研 PCB、IP67 认证、CR2032 续航长测、量产结构。

### 阶段 C｜轻量用户反馈（可与 B 并行，约 1 周）

**目标：** 小样本验证理解度与打扰感，不做增长运营。

| 任务 | 完成标准 | 建议提交说明 |
| --- | --- | --- |
| 设计 8–10 题问卷或访谈提纲 | 覆盖理解度、打扰、付费意愿 | `docs: 添加用户反馈提纲` |
| 回收样本 | ≥10 问卷或 ≥5 访谈 | `docs: 提交用户反馈原始汇总` |
| 写结论 | 三条假设成立/不成立 | `docs: 用户反馈结论与决策建议` |

### 阶段 D｜复盘与答辩（约最后 1 周）

**目标：** 诚实总结，给出下一步决策。

| 任务 | 完成标准 | 建议提交说明 |
| --- | --- | --- |
| 更新 README 完成度 | 已完成 / 模拟 / 下一步 分栏清晰 | `docs: 更新项目完成度说明` |
| 过程日志收束 | 关键时间线、失败与改进 | `docs: 添加项目复盘` |
| 3 分钟讲稿 | 能区分「已做」与「未做」 | `docs: 补充答辩讲稿` |

## 三、学生版验证指标（替代原试点硬指标）

| 维度 | 学生版指标 | 目标（小样本） |
| --- | --- | --- |
| 好伞感知 | 认同「首先是一把正常伞」的比例 | ≥ 60% |
| 概念清晰 | 正确理解「非实时定位」的比例 | ≥ 70% |
| 提醒打扰 | 认为提醒「可接受」的比例 | ≥ 50% |
| 硬件可行 | 分离提醒与寻物可复现 | 至少各成功 1 次并留记录 |
| 付费意愿 | 愿为丢后兜底付费的比例 | **只记录，不作硬门槛** |

### 结项决策（对应原「订阅上线条件」）

| 观察结果 | 学生项目结论 |
| --- | --- |
| 理解度高、打扰可接受、有一定付费意愿 | 远期可继续探索「失物场景可选订阅」 |
| 理解度高，但几乎不愿付费 | 暂缓订阅，优先打磨好伞与基础防丢 |
| 多数觉得烦或看不懂定位边界 | 先改提醒规则与文案，再谈服务 |

## 五、一句话总结

- **商业模式：** 从「怎么赚钱」改为「验证什么价值、怎么证明」。  
- **实施路线：** 从「12 个月创业」改为「本学期四阶段：原型 → 真伞验证 → 反馈 → 复盘」。  
- **提交方式：** 每完成上表一行，就做一次 Git 提交，避免期末一次性上传。
