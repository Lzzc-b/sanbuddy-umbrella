# 伞伴 SanBuddy - 智能雨伞

> **核心理念**：让用户忘记这是一把智能伞，只记得这是一把好伞。

本仓库仅保留产品方案说明。目标是减少「出门忘带伞」和「雨伞落在别处」的麻烦。设计原则：先做一把好用的伞，智能功能安静运行，付费服务只在用户主动进入失物模式后出现。

## 设计哲学

- **好伞是 1，智能是后面的 0。** 伞面、骨架、握感、重量是底线，不因智能化妥协。
- **主动性是隐性可靠，不是显性汇报。** 用户感知到的是「需要时恰好准备好了」，而非「它一直在告诉我它很忙」。
- **服务按需浮现，从不制造焦虑。** 订阅仅在失物模式中作为平等选项之一呈现，无高亮、无推荐。

## 核心功能方案

| 功能 | 方案内容 | 实际产品还需验证 |
| --- | --- | --- |
| 手动 / 半自动两款伞 | 两款智能模块相同，半自动版电子仓避开弹簧通道 | 连接强度、重量和握感 |
| 忘带伞与防丢 | 提醒规则、离开检测、最后出现位置 | 手机后台蓝牙、天气接口、通知授权和误报率 |
| 声光寻伞 | 蜂鸣器与 LED，限时停止 | BLE 控制、功耗、实际声量和防水 |
| 四级电量管理 | 低电量功能降级，可更换 CR2032 | 真实电量测量、续航和低电量阈值 |
| 电池耗尽后归还 | 无源 NFC＋印刷二维码仍可打开归还入口 | 真正可扫描标签、匿名转发服务 |
| 雨天应急与失物兜底 | 避雨、借伞、联络；失物模式中展示平等选项 | 第三方服务、售后履约和用户确认 |

**定位边界：** 「最后出现位置」记录的是手机与伞断连时的手机位置，不能代表伞的实时位置。电池完全耗尽后，BLE 无法产生新的分离事件或位置快照；已有记录仍可查看，无源 NFC 与二维码仍可使用。

## 硬件设计要点

- **两种伞型**：手动版结构较简；半自动版一键打开、手动收合。半自动版电子模块位于伞柄下部，避开弹簧空间。
- **智能伞柄**：BLE、蜂鸣器、LED、无源 NFC、可更换 CR2032；不采用充电接口、线性马达、GPS 或屏幕。
- **电池**：伞套卡槽附赠一颗备用 CR2032，伞柄底部设计免工具旋转电池仓。12–18 个月续航与 IP67 都是**设计目标**，并非已验证性能。
- **归还**：NFC 和二维码都指向同一匿名联系页。两者本身不提供定位。

## 隐私与数据安全

遵循最小权限原则，仅需附近设备、位置、通知三项权限。日程/通讯录/实时位置为可选。

| 数据类型 | 存储位置 | 加密方式 | 保留策略 |
| :--- | :--- | :--- | :--- |
| 原始 GPS 轨迹 | **仅端侧** | 系统级 | 永不上传，清除即删 |
| 常驻点标签 | 端侧为主 | TLS1.3 + AES-256 | 至用户删除/注销 |
| 位置快照 | 云端 | TLS1.3 + AES-256 | 基础 7 天 / 订阅 90 天 |
| NFC 消息 | 云端中转 | TLS1.3 | ≤24h，送达即删 |

> 以上为产品设计规范。正式产品试点前将完成第三方安全审计。

## 实施路线与验证指标

| 阶段 | 周期 | 核心目标 |
| :--- | :--- | :--- |
| **MVP** | 0–3 月 | 防丢标签 + 小程序，验证「好伞感知」与「安静防丢」基线 |
| **试点** | 3–6 月 | 一体伞样机 + 种子用户，验证下方核心指标 |
| **服务化** | 6–12 月 | 依据试点数据决策订阅上线 / 调整 / 暂缓 |

| 维度 | 核心指标 | 目标 |
| :--- | :--- | :--- |
| 好伞感知 | NPS | ≥30 |
| 提醒有效性 | 提醒-忽略比 | 2:1 – 3:1 |
| NFC 送回 | 触碰率 | ≥15% |
| 兜底接受度 | 点击率 | ≥20% |
| 应急安全 | 取消率 | <50% |
| 隐私合规 | 审计 + 自检 | 无高危，100% 通过 |
| 续航 | 低电量→更换天数 | ≤14 天 |
| 备用电池 | 首次更换完成率 | ≥80% |

> **第三阶段决策条件**：点击率 ≥20% 且 NPS ≥30 → 上线 ¥99/年订阅；点击率 10–20% 或 NPS 20–30 → 调整为一次性增值或降价；点击率 <10% 或 NPS <20 → 暂缓订阅，优先换面 / 企业定制。
