# 伞伴一体式智能伞柄：工程设计输入 V1.0

状态：**未来一体式伞柄的设计假设**。本文列出拟采用的结构、器件和验证方法，供后续工程设计使用；目前没有一体式伞柄的尺寸图、电路图、PCB、BOM 定稿或实物样机，不能据此直接加工、采购或宣称性能。本学期的验证路径仍是普通伞加市售 BLE 标签。

对应资料：[外观概念图](../prototype/hardware/concept.jpg)、[爆炸示意图](../prototype/hardware/exploded.jpg)、[H5 交互原型](../prototype/sanbuddy-prototype-v4.html)、[产品方案](product-plan-v4.1-student.md)、[本学期实施指南](implementation-guide.md)。图中的形状只表达零件关系，**没有尺寸、材料公差、装配基准或防水认证**。

### 参考伞柄基型与已知接口

后续一体式伞柄选用 **FARE 1182 自动开伞直柄**作为机械参考基型：厂家公开资料标注它为直柄、开伞按钮集成于手柄、钢制伞杆直径 **10 mm**。这里保留的是**机械开伞按钮**，已取消的仅是电子求助/SOS 按键。厂家公开尺寸属于整伞标称参数，并没有给出伞杆插入深度、开伞按钮的传动位置、弹簧端部结构或伞柄剖面；这些数据必须购买/取得实物后测绘，不能由 10 mm 伞杆外径推导。[FARE 1182 官方产品页](https://www.fare.de/de/AC.Stockschirm.FARE.Collection.Square-grau--1182/)、[FARE 产品目录](https://download.fare.de/FARE-Factbook-2023_ENOP_FARE.pdf)。

[参考布置图](handle-reference-layout-v1.svg)给出自研下部电子握柄的**布局占位值**，用于空间讨论；[立体概念图](handle-3d-concept-v1.png)展示外观、剖视和分解关系。34 mm 外径、110 mm 握柄总长、各腔分段等都是本项目提出的待验证假设，**不是 FARE 的尺寸，也不是施工图**。立体图同样不能作为零件形状和装配关系的加工依据。本项目不复制或改造厂家未公开的内部机构图；以实物测绘结果重新设计机械连接头和按钮配合。

## 1. 冻结范围与验收边界

### 1.1 本版保留

- 正常遮雨功能：手动伞，或一键开、手动收的半自动伞。
- 伞柄内 BLE、近场寻伞蜂鸣、短时 LED 提示、可更换 CR2032。
- 独立无源 NFC 与印刷二维码指向同一归还页面；它们不接电池。
- 手机侧分离提醒和断连时的**手机**位置快照。伞上无 GPS、蜂窝或远程定位。

### 1.2 本版明确删除

- **无求助/SOS 按键、触摸键、震动马达或伞柄紧急联络链路。**电路板不预留 SOS 输入、固件不定义 SOS 命令，外壳不为此开孔。
- 无充电口、扬声器网孔、裸露测试孔或外露金属电极。
- H5 的辅助联络仅是**手机屏幕上的独立演示流程**，不由伞柄触发，也不属于本硬件验收范围。

### 1.3 设计目标与放行原则

| 项目 | V1 工程目标 | 放行依据 |
| --- | --- | --- |
| 机械隔离 | 弹簧/伞杆活动件在全部开合行程内不接触电子仓 | 剖面检查、反复开合 |
| 密封 | 外壳无贯穿孔；电池盖为唯一用户可开启的密封界面 | 结构检查、装配后淋雨与进水检查 |
| 防丢 | 手机端可识别意外分离，且能区分用户主动关闭蓝牙/权限 | 锁屏及后台场景实测 |
| 寻伞 | 连接可用时发声和发光，接令后 20 秒内自动停止 | 示波器/计时/现场听测 |
| 电池 | 蜂鸣与 BLE 同时工作不掉压重启 | 新旧电池、低温工况实测 |
| 归还 | 取出电池仍可 NFC 读取、扫码访问同一入口 | 两类手机和无电测试 |

IP67、10–30 m、12–18 个月续航均不列为已实现指标。第一轮样机通过上表后，再按适用标准和测试方法确定可宣称的等级与寿命。

## 2. 出施工图前必须测绘的尺寸

选定**具体伞体型号**后，以实物测量并建立三维模型。手动与半自动版分别出图，不能只更换开伞按钮。图纸至少标注：

1. 伞杆外径、端头形状、连接方式、轴向拉拔载荷路径；弹簧外径、压缩/伸出极限和全行程包络。
2. 原伞柄外径、允许长度、握持区、挂绳位置、总重与重心。
3. 机械腔最小包络及独立封闭隔板的位置；电子腔可用内径、PCB 固定点、电池座和盖子的空间。
4. 天线周围的金属件、伞杆、CR2032 与 NFC 天线的相对位置。
5. 电池盖 O 型圈槽、止口、旋合终点、极性防错标识和用户施力部位。

**禁止按概念图比例直接下料。**尺寸冻结条件：伞可完全开合、弹簧不刮碰隔板、伞杆载荷不通过 PCB/电池仓传递、底盖可用手拆装且不会因正常握持松脱。未来 CAD 输出应包含总装、纵剖、爆炸、零件图和尺寸链；每次改版保留版号。

## 3. 机械结构与密封施工

### 3.1 结构分区

```text
伞面/伞骨 → 伞杆 → 机械连接头/弹簧腔
                         │ 独立承力隔板：无导线、螺钉或活动件穿过
                         ▼
                 密封电子腔：PCB、天线、压电发声片、LED
                         ▼
                 CR2032 电池座 → 带 O 型圈的旋转底盖
```

- 上部机械连接头只负责伞杆固定与开合载荷；电子腔位于其下方。隔板与壳体做连续实体结构，或采用工厂永久封合的独立隔仓。**开合机构不得贯通电子腔。**
- 参考自动伞的原机械开伞键位于上部机械区。本文的“电子腔密封无开孔”不表示自动伞没有机械开伞键；该键的水路和传动不得通向下部电子腔。若要整把伞柄外观完全无孔，应改选手动开伞机构并另出图。
- PCB 用塑料柱/卡槽固定在电子腔，不能以伞杆、弹簧或底盖作为定位基准。给电池、压电片及连接线留防振固定位置；挂绳座的拉力走壳体，不走电池盖或 PCB。
- 样机可先用可拆卸的塑料壳体验证内部布置，但进入淋雨样机时，除电池盖外，其余壳体接缝必须采用已验证的永久封合工艺；临时胶带不算密封结构。

### 3.2 无孔声光

- **声音：**选低功耗外驱压电片，贴合电子腔内侧的连续薄壁，使外壳振动发声。外部不设声孔。先做不同壳厚、贴合面积与位置的声量样片；若实测不够响，不能在维持“无开孔”的同时声称已达到寻伞效果，需修改壳体/发声设计并重新评审。
- **光：**LED 位于壳内，正对壳体底部的薄壁透光区。推荐用同一连续塑料壳体的局部透光/局部遮光处理；不采用贯穿外壳的独立灯珠孔。检查湿态、强光下能否辨认。
- 不让压电片或 LED 固定件顶住电池盖密封面；发声结构必须在整机装配状态下测量，裸板声量无代表性。

### 3.3 电池盖与防水

- CR2032 从底部更换；仓盖旋合至机械止挡时，对 O 型圈形成确定的轴向压缩，不能靠“拧紧手感”决定压缩量。密封槽尺寸、压缩率、公差与橡胶材料按所选 O 型圈厂商手册定稿。Parker 手册明确区分轴向面密封与径向密封，设计时不可混用槽尺寸。[O 型圈设计参考](https://www.parker.com/content/dam/Parker-com/Literature/Praedifa/Catalogs/Catalog_O-Ring-Handbook_PTD5705-EN.pdf)
- 盖内刻 CR2032 型号和正负极方向；电池触点应防反装、避免尖锐边缘损伤电池。取下底盖时应能看到 O 型圈是否缺失、扭曲或夹毛发。
- 换电池前擦干伞柄，装回前清洁密封面；更换后需做基本功能自检。电池应放在儿童无法接触的位置，备用电池袋需有防脱落设计。
- 电池盖是**唯一可开启的外界水路**，但“无开孔”不等于自动防水。要检查底盖螺纹、壳体永久接缝、透光区和伞杆连接界面。

### 3.4 NFC 与二维码

- NFC 标签采用独立无源 Type 2 标签，如 NTAG213；写入短 HTTPS 归还 URL，不与主控供电线相连。NXP 资料确认其通过读卡器射频场获得工作能量。[NTAG213 资料](https://www.nxp.com/docs/en/data-sheet/NTAG213_215_216.pdf)
- NFC 天线贴在塑料外壳内侧或封装于塑料铭牌内，避开伞杆、纽扣电池和其他金属；具体距离以实物读写测试确定。二维码印在外侧醒目位置，与 NFC 写入**同一归还入口**。
- 归还 URL 只放随机设备标识，不直接暴露姓名或电话。正式功能需要服务端建立匿名转发与失效/解绑机制；静态 H5 只能演示此流程。

## 4. 电子设计输入与原理图清单

V1 采用现成、可获得完整参考设计的 BLE SoC/模组制作工程板；**型号是候选，不是已完成选型**。例如 nRF52832 的推荐工作电压为 1.7–3.6 V，0 dBm 发射峰值电流典型约 5.3 mA；PCB 布线和天线匹配应遵循芯片/模组厂商参考设计。[Nordic 规格](https://docs.nordicsemi.com/r/bundle/ps_nrf52832/page/nrf52832_ps.html?contentId=96Da0Nf4VS5ePLinBRUs8g)

| 子系统 | 原理图必须包含 | 施工与检查点 |
| --- | --- | --- |
| 供电 | CR2032 电池座、极性保护或防错结构、SoC 所需去耦与瞬态储能 | 实测 BLE 发射＋蜂鸣＋LED 同时工作时最低电压；储能电容值由波形确定 |
| BLE | SoC/模组、天线及匹配、晶振/时钟按参考设计 | 天线净空避开伞杆、电池、手掌主要握持区；整机测 RSSI/连接稳定性 |
| 蜂鸣 | 外驱压电片、匹配的驱动级及限流/保护 | 用所选压电片数据手册确定频率、电压与驱动；不直接假定 GPIO 足够 |
| LED | 低功耗 LED、限流电阻或恒流驱动 | 限制峰值和占空比；整机测可视性与电池掉压 |
| 检测 | 电池电压采样，必要时分压器只在采样时接通 | 电量以分档显示；CR2032 负载电压不能直接换算为准确百分比 |
| 调试 | 壳内 SWD 焊盘/测试点与唯一设备序号 | 调试点不穿过外壳；封壳前烧录与测试 |
| NFC | 独立 NTAG213 标签和天线 | 无需接 MCU；取出电池仍能读出 URL |

本版无按键 GPIO、SOS 电路、充电管理、振动马达、GNSS 或蜂窝模块。

### 4.1 功耗设计门槛

以 225 mAh 理想容量计算，12 个月与 18 个月的**理论平均电流上限**分别约为 25.7 µA 和 17.1 µA；这还没扣除低温、脉冲负载、自放电和容量衰减。松下标称容量对应特定测试条件，不能用该算式承诺实际寿命。[CR2032 数据表](https://energy.panasonic.com/dam/master/pdf/en/datasheet/lithium/CR2032_Datasheet_EN.pdf)

施工时必须分别测睡眠、广播/连接、寻伞声光、低电量四种工况的电流波形，再用实际使用占空比计算寿命。若 20 秒寻伞导致复位、灯明显变暗或声量不足，应先降低功耗或调整电源方案，再讨论续航目标。

## 5. 固件和手机端接口

### 5.1 伞柄固件状态机

`未绑定广播 → 绑定/连接 → 日常低功耗连接或广播 → 收到寻伞命令 → 声光运行 ≤20 秒 → 返回日常状态`。电池不足时拒绝蜂鸣/LED 命令并返回低电状态；掉电重启后不得自动长鸣。超时停止在**伞柄固件本地**执行，不依赖手机发第二条命令。

建议的自定义 BLE GATT 特征：设备身份/版本（只读）、电池档位（只读/通知）、寻伞命令（认证后写入）、寻伞状态（通知）。绑定与命令鉴权需要防止附近陌生手机随意触发响铃；广播不得直接暴露用户身份。GATT UUID、报文格式和密钥更新在固件实现前冻结成接口表。

### 5.2 手机端职责与限制

- 手机负责用户授权、绑定、通知、分离判定和“断连时手机位置”记录；伞柄只提供 BLE 可见性、声光执行与电池状态。
- 判定分离需有等待窗口和重新连接检查；关闭蓝牙、权限撤销、手机关机、用户主动借伞都要显示不同状态，不能一律提示“伞丢了”。
- 真正的后台提醒需要原生手机端设计和锁屏测试。iOS Core Bluetooth 与 Android 后台 BLE 均有系统级运行条件；现有 H5 不能作为后台可靠性证明。[Apple 文档](https://developer.apple.com/documentation/xcode/configuring-background-execution-modes)、[Android 文档](https://developer.android.com/develop/connectivity/bluetooth/ble/background)

## 7. 图纸与样机齐备后的拟定装配工序

1. **来料核对：**核对伞体型号、弹簧行程、电池极性、PCB 版本、NFC URL、O 型圈规格；不合格件隔离。
2. **机械预装：**先装伞杆连接头和弹簧腔，完成开合及拉拔检查，再固定连续隔板；从电子仓侧确认没有可见贯通孔和活动件侵入。
3. **电子预检：**裸板烧录、记录序号、验证 BLE 广播/连接、电池档位、蜂鸣、LED 及 20 秒超时；测峰值电流和电压。
4. **封装电子仓：**固定 PCB、天线、压电片与 LED；检查发声贴合与天线净空；完成非用户接缝的永久封合。
5. **装电池与底盖：**检查密封面、正确放置 O 型圈和电池，旋至机械止挡；标记底盖位置便于松动检查。
6. **贴标：**NFC 与二维码写同一设备入口，取出电池做两次读取；确认标签不会被金属件遮挡。
7. **整机复检：**开合、握持、寻伞、连接、换电后再次寻伞；完成第 8 节测试记录。任一结构改动都重新做密封与声量测试。

## 8. 未来首轮样机的测试计划

每个样机记录版本、伞体型号、电池品牌/批次、手机型号/系统版本、测试日期与操作者。不能只记录成功案例。

| 项目 | 方法 | 通过条件（第一轮工程门槛） |
| --- | --- | --- |
| 开合/隔离 | 手动与半自动分别完成至少 100 次完整开合，再拆检 | 无卡滞、隔板磨痕、导线受力或 PCB 松动 |
| 连接/提醒 | 室内、走廊、室外各做分离及重新接近；含锁屏和后台 | 每次记录实际提示时间、漏报和误报；未完成前不宣称可靠 |
| 声光 | 装壳后在安静及普通环境测可听/可见性 | 可辨认，且收到手机停止命令或运行 20 秒后自动停止；记录距离和环境噪声 |
| 电池 | 新电池、使用中电池及低温后执行声光命令 | 不复位、不误报电量；记录最低电压与电流波形 |
| 密封 | 未开盖、换电后各做淋雨与擦干开盖检查 | 电子仓无可见水迹；失败时定位水路并重做，不宣称 IP 等级 |
| NFC/二维码 | 取出 CR2032 后，用不同手机触碰/扫码 | 均打开同一归还入口，且不显示失主私人联系方式 |
| 装配维护 | 非设计人员按说明更换电池并复测 | 不反装、不夹伤 O 型圈，底盖可固定且功能恢复 |

若要正式宣称 IP67，必须按适用标准确定试验条件，对**最终材料、最终装配工艺和多件样品**进行相应测试；本表的淋雨检查不等于 IP67。

## 9. 暂停点与下一版决策

出现以下任一情况，暂停外观定稿：密封壳体下蜂鸣听不清；压电片与 BLE 同时工作导致复位；电池盖换装后渗水；弹簧腔侵入电子空间；握柄过粗/过重；锁屏后台提醒不可靠；NFC 被金属遮挡。每个问题需记录“测试条件 → 结果 → 修改 → 复测”，再决定保留 CR2032、调整声光目标或更改结构。

**本文件不是施工定稿。**至少需要定版伞体、测绘与公差、机械总装和零件图、电路图与 PCB、按具体料号列出的 BOM、固件/手机接口、装配工艺，再经设计审查后，才能另发“可施工图纸包”。样机与测试记录是性能宣称的后续条件，不能由图纸代替。
