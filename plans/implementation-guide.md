# 伞伴项目实施指南（对齐 V4.1 学生版）

> **定位：** [`product-plan-v4.1-student.md`](product-plan-v4.1-student.md) 的执行手册。  
> **原则：** 方案 + 可演示 H5 + 低成本硬件验证 + Git 过程留痕；本学期不做真实收费、不上架微信小程序。  
> **保留：** Cloudflare Pages、PWA。  
> **不做：** Vite 生产构建 / 类小程序码 / 演示视频硬要求；不预建空 `tests/` 模板。  
> **写法：** 下列步骤按产品推进；每步操作已写清须留下的工程证据（运行说明、Git、分支、约定、回归、复盘等）。
> **范围互链：** [产品方案](product-plan-v4.1-student.md)写目标，[H5 原型](../prototype/sanbuddy-prototype-v4.html)演示流程；[一体式伞柄工程设计输入](hardware-design-input-v1.md)属于远期方案，尚无施工图或样机，不计入本学期硬件验证完成度。

---

## 一、三阶段总览

| 阶段 | 时间 | 核心任务 |
|------|------|----------|
| 一 · 概念与原型 | 第 1–2 周 | 可运行交付、验收标准、首次交接与同伴反馈；Git 快照 / 原子提交 / 读 diff / 可控恢复 |
| 二 · 硬件与协作 | 第 3–7 周 | 真伞最小验证；双方案分支对比取舍；仓库约定、`AGENTS.md`、无损交接 |
| 三 · 收束与复盘 | 约第 10–13 周 | 「三不」范围、PR 审阅与回归；微里程碑与开源协作；人机复盘；可选结项工程包 |

**提交原则：** 每完成一小步就 `git commit` 一次；一次提交只做一类事；禁止无必要的 `push --force`；回退用 `git restore` / `git revert`，保留历史。

## 二、阶段一：概念与原型（第 1–2 周）

本阶段要同时留下两类证据：**产品能演示**，以及 **运行/验收/交接/Git 过程可核验**。

### 2.1 操作步骤

| 步骤 | 具体操作 | 产出 | 建议 Commit |
|------|----------|------|-------------|
| 1-1 | **环境隔离与怎么运行**<br>约定只用本仓库静态文件打开原型（本地双击 / 简易静态服务），不依赖本机全局乱装工具；写清：克隆后打开哪一页、Pages 预留位置 | README「快速开始」 | `docs: 补充运行与打开说明` |
| 1-2 | **写完成标准（验收约定）**<br>可勾选清单，例如：引导可走完、有模拟标识、非实时定位说清、失物页无推销高亮、Pages/PWA 是否已验证 | README「本阶段验收约定」 | `docs: 添加本周验收约定` |
| 1-3 | **手动提交说明**<br>每次有意义改动：commit message 写清「改了什么 / 为什么」；必要时在 README 用两三句话概括本周个人贡献 | 可读的提交说明 | 随功能提交 |
| 1-4 | **首次交接 + 同伴试跑**<br>把「快速开始 + 验收约定」发给同学；请其只凭文档打开并走主流程；收集 3–5 条反馈，**脱敏**后写入过程摘录 | 试跑反馈摘要 | `docs: 记录同伴试跑反馈` |
| 1-5 | **理解仓库快照**<br>改动前 `git status`，对照 `git log --oneline` 知道当前基线；重要节点确认工作区干净 | 习惯与时间线 | （过程，不一定单独提交） |
| 1-6 | **原子提交**<br>一次提交只做一类事（例：只改文档 / 只加二维码）；禁止把无关文件打进同一包 | 清晰历史 | 规范 message |
| 1-7 | **读 diff 再提交**<br>提交前 `git diff` / `git diff --staged`：确认无密钥、无损坏编码、无半成品目录 | 自审记录（可写进过程摘录） | 规范提交 |
| 1-8 | **可控恢复演练**<br>① 未提交误改：`git restore <文件>` 还原；② 已推送误提交：故意小改 → `git revert` → 推送（**不** `push --force`） | restore / revert 各留痕迹 | `revert: …` |
| 1-9 | **原型对照方案自查**<br>3 步引导、非实时定位文案、寻伞限时、失物平等选项、模拟数据标识 | 自查结论短文 | `docs: 原型对照方案自查` |
| 1-10 | **确认 / 小改交互**<br>缺什么补什么；V4 已覆盖主流程则可少改 | 可打开的原型 | `feat: …`（有改动时） |
| 1-11 | **PWA**<br>`manifest.json`、图标、页面引用；「添加到主屏幕」须在 HTTPS（Pages）上验证；**不做** Service Worker 离线缓存 | PWA 真机验证说明 | `feat:` / `docs:` |
| 1-12 | **部署 Cloudflare Pages**<br>见 §2.2；手机 4G 打开验证；链接写入 README | 公网链接 | `docs: 记录 Pages 部署链接` |
| 1-13 | **H5 体验二维码（可选）**<br>Pages 链接做成普通二维码；**标注「H5 演示，非微信小程序」** | `prototype/qrcode-h5.png` | `assets: 添加 H5 体验二维码` |
| 1-14 | **更新体验入口**<br>README 汇总：Pages、二维码、本地打开、PWA、模拟边界、验收勾选 | README | `docs: README 增加体验入口` |

### 2.2 Cloudflare Pages

静态 HTML，**无需** `pnpm build`。

1. 打开 [Cloudflare Pages](https://pages.cloudflare.com/)，用 GitHub 登录。  
2. 连接仓库 `Lzzc-b/sanbuddy-umbrella`。  
3. Framework = **None**；Build command = **留空**；Build output directory = **`prototype`**。  
4. 入口为 `prototype/index.html`（跳转 V4 原型）。  
5. 把链接写进 README 后再提交一次。  

**当前在线地址：** https://sanbuddy-umbrella.pages.dev/  

**体验二维码：** [`prototype/qrcode-h5.png`](../prototype/qrcode-h5.png)（扫码打开上述 H5；**非微信小程序**）。

### 2.3 PWA

- `prototype/manifest.json`、`prototype/icons/`、原型页引用  
- **不做** Service Worker 离线缓存  
- 在 Pages 的 HTTPS 域名上测「添加到主屏幕」

### 2.4 阶段一完成标志

- [x] 运行说明 + 验收约定已写；环境按「只开本仓库静态页」隔离说明清楚

- [x] 提交历史可读；有 `diff` 自审习惯；有 `restore`/`revert` 可控恢复痕迹  
- [x] Pages 主流程可走通；PWA 可加主屏幕

## 三、阶段二：硬件验证与仓库约定（第 3–7 周）

本阶段只验证“普通伞 + 市售 BLE 标签”的真实表现。即使测试成功，也只能说明所用标签在记录的场景下工作，不能证明[一体式伞柄方案](hardware-design-input-v1.md)已实现；实测照片和日志仍需另行入库。

本阶段要留下：**双方案分支取舍证据**、**系统约定与 AI 上下文（AGENTS.md）**、**他人可无损接手**，以及真伞最小验证。

### 3.1 低成本物料（参考）

| 物料 | 建议 | 预算 |
|------|------|------|
| 伞 | 自有 / 借用 | ¥0 |
| BLE 防丢标签 | 「蓝牙防丢器 双向查找 蜂鸣器」白牌 | ¥15–20 |
| NFC（可选） | NTAG215 | ¥数元 |
| 固定 | 胶带 / 橡皮筋 | ¥2 内 |

**选购：** 要双向查找 + 蜂鸣；不要 GPS；不要开放 SDK。

### 3.2 操作步骤

| 步骤 | 具体操作 | 产出 | 建议 Commit |
|------|----------|------|-------------|
| 2-1 | 采购并验收：配对、蜂鸣、伞柄能否固定 | 选型说明 | `docs: 记录真伞与标签选型` |
| 2-2 | 安装并拍照（建议本人同框；控制图片体积） | 实拍 | `docs: 上传安装实拍` |
| 2-3 | 分离提醒实测 ≥1 次（环境、距离、结果） | 实测记录 | `test: BLE 分离提醒实测` |
| 2-4 | 声光寻物实测 ≥1 次 | 实测记录 | `test: 声光寻物实测` |
| 2-5 | （可选）NFC 写入 Pages 链接；取出电池后仍可读 | 记录 / 截图 | `test: NFC 无电读取` |
| 2-6 | 写清局限：非 IP67、非长测续航、胶带临时固定等 | 验证小结 | `docs: 硬件验证小结与局限` |
| 2-7 | **远程协作基线**<br>确认 `main` 与远端同步；约定功能只在分支上改，经审阅再合入 | 远端一致的基线 | push / pull 过程 |
| 2-8 | **双方案：开两条特性分支**<br>从同一 commit 拉出例如 `trial/copy-a` 与 `trial/copy-b`（或布局 / Pages 配置两种做法） | 两个远程分支 | 分支推送 |
| 2-9 | **对比与取舍证据**<br>写短文：标准是什么、为何选留、另一方案为何放弃；用 PR 描述或 `docs` 固化 | 对比短文 + PR | `docs: 双方案对比` |
| 2-10 | **合并或选留一条**<br>合并到 `main`（或明确废弃分支并写原因）；保留讨论与 diff 可回看 | 取舍后的主线 | merge / close |
| 2-11 | **系统约定（仓库契约）**<br>目录含义、模拟边界、Pages 输出=`prototype`、禁止事项写进 README / 本手册 | 约定文档 | `docs: 明确仓库约定` |
| 2-12 | **落地 `AGENTS.md`**<br>给协作者/AI：结构、能改/不能改、如何提交、隐私脱敏；与真实目录一致 | 根目录 `AGENTS.md` | `docs: 添加 AGENTS.md` |
| 2-13 | **个人贡献可核对**<br>用 `git log` / PR 列表能指出「哪些是你决策与验收、哪些是协助」；必要时在 README 写一小段贡献说明 | 可核对的贡献叙述 | `docs:`（如有） |
| 2-14 | **无损交接验收**<br>换一台设备或请同学：**只凭 README + AGENTS.md**（不口头补充）独立打开 Pages/本地并完成验收勾选 | 交接记录一小节 | `docs: 交接验收记录` |

**不做：** 自研主板、IP67 认证、量产、真实支付。

### 3.3 阶段二完成标志

- [ ] 分离提醒、寻物各成功 ≥1 次并有记录/照片；局限已写明  
- [ ] 两条特性分支 + 对比取舍文字 + 合并/废弃记录可查  
- [x] `AGENTS.md` 与仓库约定已落地  
- [ ] 他人仅凭文档可打开并完成交接验收

## 四、阶段三：收束与复盘（约第 10–13 周）

本阶段要留下：**范围「三不」**、**PR 审阅与真回归（禁止假修）**、**微里程碑 / README 盲测 / 许可证与贡献响应**、**基于真实 Git 的人机复盘**；有余力再做结项工程包。

### 4.1 操作步骤

| 步骤 | 具体操作 | 产出 | 建议 Commit |
|------|----------|------|-------------|
| 3-1 | **范围「三不」**<br>写死本学期不做：真实支付、上架微信小程序、自研主板（可按实际再补 1～2 条） | README 或短文 | `docs: 明确项目范围` |
| 3-2 | **改动走 Pull Request**<br>功能/文档走分支 → PR；自己或同学按 checklist 看过再合并；PR 里写清目的与风险 | PR 记录 | 通过 PR 合并 |
| 3-3 | **回归用例（可重复走查）**<br>固定步骤：引导 → 首页 → 寻伞 → 电量 → 失物；写进 README 或短文；**每次合并前跑一遍** | 走查清单 | `docs:` / `fix:` |
| 3-4 | **防假修**<br>回归失败先修再合；禁止「只改文案假装修好」或跳过走查；坏了在 PR/过程里如实写 | 失败与修复记录 | 真实提交 |
| 3-5 | **微里程碑勾选**<br>「Pages 可开」「PWA 可加主屏」「分离提醒实测 1 次」等在 README 可核验勾选，完成一项勾一项 | README 完成度 | 分次提交 |
| 3-6 | **README 盲测**<br>陌生人（或换设备）只凭 README：克隆 → 打开或访问 Pages → 按验收点点一遍；不通则改文档直到通 | 盲测记录 | `docs: README 无损复现` |
| 3-7 | **开放协作**<br>写清如何提 Issue/建议；有 Issue/PR 及时回应（哪怕只是确认收到） | README 贡献说明 | `docs: 补充贡献说明` |
| 3-8 | **开源许可证**<br>根目录 `LICENSE`（建议 MIT）；与仓库公开方式一致 | `LICENSE` | `docs: 添加 LICENSE` |
| 3-9 | **更新完成度分栏**<br>已完成 / 仍为模拟 / 下一步 分开写，避免夸大 | README | `docs: 更新项目完成度` |
| 3-10 | **过程日志**<br>关键时间线、失败、改进（可与试跑反馈合并为一篇） | 过程日志 md | `docs: 添加过程日志` |
| 3-11 | **人机协作复盘（须有 Git 事实）**<br>基于真实 `git log` / diff / PR：哪些你决策与验收、哪些 AI 起草或改文件、得失与下次改进；写进 `plans/ai-collab-review.md` | 复盘文 | `docs: 添加协作复盘` |
| 3-12 | **3 分钟讲稿**<br>分清已做与未做、演示路径、边界（模拟 / 非实时定位） | 讲稿 md | `docs: 添加答辩讲稿` |
| 3-13 | **（可选）结项工程包**<br>仓库洁净：无密钥、无半成品、无无关大文件；回归走查全绿；关键决策（为何 H5 / 白牌标签 / Pages+PWA）有据可查 | 干净仓库 + 决策说明 | `chore:` / `docs:` |
| 3-14 | （可选）打 Tag：`v1.0.0-student-final` | Git Tag | `git tag` + `git push --tags` |
